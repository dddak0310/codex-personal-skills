# 版型清單與容量上限

投影片固定 **1600×900**（16:9），截圖 @2x = 3200×1800。
**投影片上的文字一律用英文**（實驗室有外籍生）。字數上限以英文計。
下方的上限是「排得下且好讀」的經驗值，`check_deck.py` 會擋；
但**真正的把關是 `shoot.py` 的實際量測**——`.slide` 是 `overflow:hidden`，
超出的內容會被靜靜裁掉，所以截圖前一定要量。

> 呈現是**一次性投資**：版型做出來之後，每週只是「這頁用第幾種」，不是重新設計。
> 覺得都不合用再新增版型，並在此登記。

| type | 長相 | body 欄位 | 容量上限 | 預設底色 |
|---|---|---|---|---|
| **`diagram`** | **圖解（第一選擇）** | `src`（.svg 路徑）或 `svg`（內嵌字串）、`caption` | 圖自己控制 | 白 |
| **`example`** | **機制頁：案例主圖佔滿全版（無側欄）** | `src`（.svg 路徑）或 `svg`（內嵌字串） | 圖自己控制，但要吃滿版面預算（§`example`） | 白 |
| `agenda` | 編號清單（outline，**簡報的第一頁**） | `items:[{n,t,d}]`（**`t` 必填**） | ＝ `user_points` 條數；上限由 `MAX_PER_THREAD` 推導（`check_deck.py --limits` 印 `agenda`；⛔ 這裡不寫數字，B17-11） | 白 |
| `thread-intro` | **只用於 backup 分隔頁** | `label` `title`（`sub` 選填） | 標題 ≤ 2 行 | 深藍 |
| `table` | 表格（主力版型） | `tables:[{caption,columns,rows,align}]` | ≤ 2 張表；每張 ≤ **8 列 × 9 欄**；儲存格 ≤ **78 字** | 白 |
| `stats` | 大數字並排 | `items:[{v,k,hl}]` | ≤ 4 個 | 白 |
| `cols` | 兩欄對照（**需 `why_text`**，多半該改畫成圖） | `left` `right`（各 `{h,tone,items,text,table}`） | 每欄 ≤ 6 項 | 白 |
| `flow` | 流程步驟（箭頭串接） | `steps:[{n,t,d}]` | ≤ 5 步 | 白 |
| **`pipeline`** | **單向流程（可多 lane，節點內放清單／數字／色塊）** | `lanes:[{label,note,tone,nodes:[{n,t,d,items,codes,v,chip,arrow,tone}]}]` | ≤ 3 lane（建議 2）；每 lane ≤ 5 節點；每節點 `items` ≤ 4、`codes` ≤ 4 | 白 |
| `points` | 條列（**下下策，需 `why_text`**） | `items:[]` | ≤ 6 項，每項 ≤ 100 字 | 白 |
| `issues` | 問題清單（**僅限 backup**，需 `why_text`） | `items:[{t,d,r}]` | ≤ 4 項 | 白 |
| `figure` | 現成點陣圖檔 | `src` `caption` | 自行控制長寬比 | 白 |
| `cover` | 封面 | `kicker` `title` `range`（三個都必填） | — | 深藍 |

⚠️ 這三種**結構頁**的 `body` 哪些欄位是必填（缺了 `render_deck.py` 會當場崩，
而不是只是難看），**唯一定義在 `deck_schema.md`「結構頁」那一節** —— ⛔ 這裡不再抄一份。

### `example`：機制的預設版型

適用於 `depth: mechanism`。主圖**佔滿整個版面**，用**一個具體案例**呈現
`before → operation → after`，而**可重做的規則與其邊界要畫在圖裡面**
（門檻標在操作那一格、邊界畫成不適用的那一支）——⛔ 沒有側欄可以放它們了。
例子可以是 observed 或 constructed；constructed 必須在投影片或講稿清楚標示為示意。

⚠️ 全幅之後**版面預算變成整頁**：主圖若只畫到約六成高就會留下大片空白，
而「容器過空」對主線內容頁是會擋的。版面預算查 `diagram-craft.md §6`，
填料的辦法見 `presentation_rules.md §6`。

### `pipeline`：什麼時候用、上限是怎麼算出來的

**這是「單向線性流程」的第一選擇**（`composition-vocabulary.md` Step ⓪b 路由表第一格）。
純 CSS flex，**不用管座標**，節點內能塞清單、大數字、色塊 —— 比手刻 SVG 便宜一個數量級。

`flow` 與 `pipeline` 的分工：
- **`flow`** —— 三五個**等重**步驟，每步只有一句話。單排，不分 lane。
- **`pipeline`** —— 步驟裡要放東西（清單／數字／色塊／產出物名），或**同時有兩條並行的路**
  （建置路徑 vs 計分路徑、離線 vs 線上）。

⛔ **只走單一方向。** 要分支、要回圈、要精準控位 → 不要硬用，走路由表下面那格（手刻 SVG）。
硬用會得到一張「箭頭都對、但意思是錯的」圖。

**容量上限的依據**（不是隨手訂的數字，`check_deck.py` 會擋）：

| 上限 | 怎麼算的 |
|---|---|
| lane ≤ **3**（建議 2） | 可用高 ≈ 900 − 2×72(padding) − 標題區 ≈ 612px；一條 lane（標題列 + 節點）約 200px，加 24px gap → 3 條 ≈ 648px 已經超出。實測 2 lane × 3 節點且每節點放兩項清單時，`shoot.py` 就報「子內容溢出」 |
| 每 lane 節點 ≤ **5** | 內容寬 = 1600 − 2×72 = 1456，扣 lane 內距 → 1412；箭頭固定 66px。5 節點 → 每個 ≈ 230px；6 節點只剩 ≈ 191px，放不下「標題 + 一行內容 + 產出物 chip」而不折成三四行 |
| `items` ≤ **4**、`codes` ≤ **4** | 再多就撐爆節點高度，把整條 lane 拉高 |

⚠️ **同一條 lane 內的節點內容量要相當。** 節點是等高對齊的，一個節點放三項清單、
旁邊只放一句話時，`shoot.py` 會報「容器過空」—— **那是對的**，不要去關掉它，
要嘛把空的那個補內容，要嘛把滿的那個拆掉一項。

**節點四種填法**（依資料性質選，可疊）：`d` 一句短標籤／`items` 清單／`v` 一個大數字／
`codes` 色塊。`chip` 是這一步的**產出物名**，釘在節點底部，一整排才會對齊成一條線。
`arrow` 是**流進**這個節點的東西的名字（所以第一個節點不能有 `arrow`）。

**顏色**：`tone` 只有 `good`（綠＝新／改善／保留）、`bad`（紅＝舊／問題／移除）、
`hl`（金＝這一頁要你看的那個）三種，lane 與 node 各自可設。⛔ 不要為了好看再開第四種
—— `presentation_rules §5`「同一個顏色只能有一種意思」。
⚠️ **刻意不移植來源那組七色節點漸層**（藍→靛→紫→琥珀→青→綠→紅）：那組色是「第幾步」
的編號色，會跟我們既有的紅／綠／金語意打架。步驟編號用 `n` 的圓形 badge 表示就夠了。

> ⭐ **表格容量的數字以 `check_deck.py` 的 `LIMITS` 為準**（N63，批次 5g 定案）：
> `table_rows=8`、`table_cols=9`、`cell=78` —— **會擋的是那一份**。
> 這裡的 9／78 是抄過來的副本，⛔ 改要改那邊。
> ⚠️ 舊版這裡寫 6 欄／56 字，比程式**嚴**：builder 照主檔會**白白拆頁、砍字**，
> 而且沒有任何東西會告訴它那是多餘的。欄數放寬到 9 是刻意的
> （符號矩陣 O／X／~ 的欄很窄，理由寫在 `LIMITS` 旁邊）。

### ⭐ `table`：「造成什麼／代價」欄每列至少一個**可數的**代價

表格如果有一欄在講**後果／代價**（「造成什麼」「what it cost」「影響」），
**那一欄的每一列都要有一個數得出來的量**：頁數、輪數、筆數、時間、次數。

- ✅「7 頁規劃只有 2 頁是要的」「checker 誤判 7/8 頁」「一張圖改 4 輪」
- ❌「只對了一半」「花了不少時間」「規格和我想的不一樣」 ← 敘述句，聽眾比不出輕重

**數不出來的那一列，降到 `notes` 口頭講**，⛔ 不要留在表上湊列數。

> **為什麼**：代價欄是聽眾唯一用來比較「哪個問題比較嚴重」的東西，
> 沒有數字就只剩語氣。人工成品的同一張表**每一列都有數字**，
> 上一次盲測的對應那張中欄**一個數字都沒有**（FINDINGS G4）。
> ⚠️ 數字一樣受數字溯源約束：逐字照抄來源，不得計算（`deck_schema.md`「數字的規矩」）。

### 表格內的比例 bar

儲存格除了字串，也可以寫 `{"v": "53/66", "pct": 80.3, "tone": "bad"}` ——
上面一行數值、下面一條寬度＝比例的色條。

⚠️ **一定要同時給 `colw`（固定欄寬），`check_deck.py` 會擋。** 這條不顯而易見，
但少了它 bar 就沒有意義：純 HTML table 沒有指定寬度時欄寬隨內容撐開，
**同一個 80% 在窄欄與寬欄畫出來的像素長度不同，肉眼比不出誰的比例高**。
**多張表要跨表比較時，兩張的 `colw` 要給同一組寬度。**

⚠️ `pct` 是**幾何不是文字**，不會印在投影片上，所以它逃得過數字溯源檢查。
`v` 寫成 `a/b` 時 `check_deck.py` 會回頭驗一次 `pct ≈ 100a/b`（差 >1 個百分點就擋）——
bar 的長度是讀者用來比高低的東西，寫錯了畫面上完全看不出來。

**列標記** `rowclass:["","drop","hl",…]`（與 `rows` 等長）：`drop` = 這一列被移除
（紅底刪除線，第一欄不畫線 —— 名字要讀得出來才知道刪掉的是誰）、`hl` = 這一列是重點（金底）。

> ⛔ `cover`、「本週的問題與結論」頁、**以及線的開場頁**一律不使用 —— 簡報從 `agenda` 直接開始，
> 每條線的標題寫在議程頁上，換線由講者口頭引導即可
> ——一張只有標題的分隔頁不會增加任何資訊。
> `thread-intro` 現在只剩一個用途：**backup 區的分隔頁**。

### ⭐ 後續修訂：**線的 outline 頁要用，但只有「列出重點」那一種**

使用者在首次實跑時要求：**每條線前面都要有一張 outline，說明接下來要講什麼；
最前面也要有一張全場 outline**，講本週有哪幾個主題；並澄清那張 outline 的內容
**就是每一頁的 topic 而已**。

⚠️ 這**看起來**推翻了上一版實跑的「線的開場頁一律不使用」，但兩者管的不是同一種頁：

| | 上一版實跑否決的 | 首次實跑要求的 |
|---|---|---|
| 內容 | **只有線的標題**（＋一句 sub） | **列出這條線每一頁的 topic** |
| 資訊量 | 零 —— 標題在議程頁上已經有了 | 聽眾知道接下來四頁各講什麼 |
| 當時的理由 | 「一張只有標題的分隔頁不會增加任何資訊」 | 「說明接下來要講什麼」 |

**所以舊規則沒有被推翻，是被縮小了適用範圍**：擋的一直是「零資訊的分隔頁」。

**現行做法**：三種 outline（全場／每條線／backup 分隔頁）——
⭐ **哪一種要有、內容是什麼、項數怎麼算，唯一定義在 `SKILL.md`「outline 頁」那一節**，
⛔ **這裡不再抄一份**。本檔只管長相：全場與各線的 outline 用 `agenda` 版型，
backup 分隔頁用 `thread-intro`。

> ⚠️ 舊版在這裡寫「項數＝該線的**內容頁數**」，而 `SKILL.md` 寫「逐字抄
> `user_points`」——**兩處分岔**，實測那一次是 5 對 4（FINDINGS N24）。
> `check_deck.py` 比對的是 `user_points` 的條數，所以本檔那一句是錯的，已刪。

⛔ 仍然禁止：只有標題沒有列出重點的線開場頁（那正是上一版實跑砍掉的東西）。

> 週敘事（PMRC）是 `deck.json` 的 `arc` 規劃欄位，不佔投影片。
> `issues` 只用於 backup；主線上不放「待決與下一步」。

> ⚠️ 用字與標註的規矩（名詞規範、文字白名單、一頁只放一種視覺）在
> **`presentation_rules.md`**，那份與本檔並行——本檔管長相，那份管每頁都適用的規則。

## 挑版型的順序：圖 > 表 > 文字
<!-- @for: planner,builder -->

```
這頁要講的東西長什麼樣？
├─ 因果鏈（A 導致 B 導致 C）      → diagram：橫向方框 + 箭頭。⛔ 結果那格**不塗強調色** ——
│                                     要它突出就放大／放最後，或在格內放一處金字（6c）
├─ 前後對照（以前這樣／現在那樣）→ diagram：上下兩排，舊的 .box-bad、新的 .box-good
├─ 流程順序                       → 先查路由表：單向線性 → pipeline；
│                                    只是三五個等重步驟 → flow；有分支回圈 → diagram
├─ 數值大小比較                   → diagram：長條圖幾乎永遠比表格好讀
├─ 多欄位的對照數據               → table
├─ 三四個關鍵數字要被記住         → stats
└─ 以上都不是                     → 先問這頁該不該存在。
                                     真的要，用 points 並在 why_text 寫出理由
```

⚠️ **`points` / `cols` / `issues` 沒有 `why_text` 會被 `check_deck.py` 擋下。**
文字不是預設，是下下策。

## 共用元件
<!-- @for: builder -->

- `tone: "dark"` 深藍底、`"soft"` 淺灰底 —— 用來做**節奏**：
  深色開場 → 淺色內容 → 深色分隔 → 淺色 backup
- ⛔ `takeaway` 底部色條 —— **已移除**（不只是「不要用」：渲染、CSS、字數上限、
  高度預算都已拆掉，N67）。結論不上投影片，寫進 `notes` 的「【口頭結論】」
- **主題編號**：多線時每頁左上自動標「① 主題標題」，對應議程頁的 1／2／3。
  由 `deck.threads` 的順序產生，不要手寫。
  ⚠️ 這與先前拿掉的「線標籤」不同——那是一個沒有意義的代號（`可信度`），
  這是**聽眾在議程頁看過的編號**。編號對不上時，
  聽眾會以為還在講第 1 條，其實已經換到第 2 條了。
- 表格欄位 `align: ["", "num", "num"]` 把該欄改為右對齊等寬數字

## 寫 SVG 的規矩
<!-- @for: builder -->

1. **一律用外部 `figures/*.svg` 檔**，由 `render_deck.py` **內嵌**進 HTML。
   ⛔ 不要用 `<img src="x.svg">` —— 那樣 SVG 是獨立文件，`deck.css` 完全不會套用，
   所有圖形會退成**預設黑色**（上一版實跑踩過一次，整張圖變黑方塊）。
2. **不要在 SVG 裡寫顏色，也不要寫 `<style>` 區塊**，改用 `deck.css` 已定義的 class：
   ⚠️ `<style>` 區塊會被中文對照表的字串收集器當成待翻文字撈進去
   （上一版實跑踩過：六行 CSS 變成六筆待翻字串）。`render_deck.py` 現在會跳過含 `{}` 的內容，
   但正確做法仍是把樣式寫進 `deck.css`。

   | class | 用途 |
   |---|---|
   | `.box` `.box-bad` `.box-good` `.box-null` `.box-ctl` | 方框：一般／舊或壞／新或好／預期歸零／控制變數。⛔ **沒有 `.box-hl`**（6c 廢除） |
   | `.bar` | 長條圖。⛔ **沒有 `.bar-hl`**（6c 廢除） |
   | `.arrow` | 箭頭（需在 SVG 內定義 `marker id="a"`）。⛔ **沒有 `.arrow-hl`**（6c 廢除） |
   | `.rule` | 分隔線 |
   | `.label` `.label.lead` | **東西的名字**（節點名、箭頭標籤、欄位名）／群組或區塊的主名 |
   | `.label.section` | 盒內的**分段標題**（`Every item carries`／`Limits`） |
   | `.label.term` `.label.gloss` | 定義列**左欄的詞條**／**右欄那一句話** |
   | `.label.num` | 編號欄的**序號**（畫在 `.pill` 上） |
   | `.value` `.value.inline` | **數字／結果**（大數字）／跟在標籤後面的小數值 |
   | `.annot` | **這張圖怎麼讀**（每頁 ≤2，與 `sub`／`caption` 合併計數） |
   | `.def` | **名詞定義**（每頁 ≤1，同上合併計數） |
   | `.hl` | 強調，**疊在上面四種之一**（例：`class="value hl"`），⛔ 不能單獨用 |
   | `.grp` `.grp-bad` `.grp-good` `.grp-null` `.grp-ctl` | 分群清單的框：一般／舊或壞／新或好／預期歸零／控制變數。⛔ **沒有 `.grp-hl`**（6c 廢除） |
   | `.grp-h` `.item` | 群標題／群裡的項目（等寬字） |
   | `.file` `.file-bar` `.file-name` `.file-line` | 檔案節錄：外框／檔名列／檔名／內容行 |

   ⛔ **每個 `<text>` 必須恰好帶一個用途 class**（`label`／`value`／`annot`／`def`）——
   `check_deck.py` 的 `check_purpose()` 機械檢查，少標、多標、超額各是一條 ERROR。
   ⛔ **`.t-lg` `.t-md` `.t-sm` `.t-num` 已作廢**（`check_deck.py` 的 `LEGACY_CLASS`，
   逐則報 ERROR）。它們編的是「這句話**多大**」，於是寫圖的 agent 只被問字級、
   沒有任何一個選項會讓他發現「這是旁白，不該存在」——
   新字彙編的是「這句話的**用途**」，額度是從用途推出來的。
   ⚠️ `deck.css` 還留著那五個 class，那只是為了讓既有的圖還渲染得出來，⛔ 不是可用的字彙。

   ⛔ **`<text>` 一律不得帶 inline `font-size`／`font-weight`／`letter-spacing`**
   （`check_deck.py` 的 `check_inline_type()`，逐則 **ERROR**）。
   ⭐ **層級只准有一個來源 —— 字彙**。以前 `label` 底下只有 `label` 與 `label.lead`
   兩級，盒子裡實際需要的四級**在字彙裡不存在**，於是每張圖各自用 inline style 硬補
   （實測 7 張圖 31 處字級、25 處字重的覆寫）——
   **每張圖發明的值不保證一樣，就是「粗糙」與跨頁不一致的來源。**
   需要新層級時的正解是**在 `deck.css` 加一個角色 class**，⛔ 不是在圖上寫 style。
   ⚠️ `font-family` 不在禁令裡（等寬是「這是字面／檔名」的語意記號，與字級層級正交）。

   ⚠️ CSS class 會蓋掉 SVG 的 `fill=` 屬性。要局部換色就另外開一個 class，不要寫 inline。
   ⛔ 淺色只給 `annot` 與 `def`（它們在結構上最多 3 則）；`label`／`value` 是圖的一部分，
   不是註解，一律正常色。
3. **viewBox 用 `0 0 1420 <高>`**。寬固定 1420；⛔ **高不要抓一個範圍**，
   去 `diagram-craft.md §6` 的表查 —— 這頁有沒有 `topic`／`sub` 就差好幾十 px
   （⚠️ `takeaway` 已停用，⛔ 不要再拿它當組成的一項，N67）
   （444 vs 636），⛔ 那張表是唯一的出處，這裡不重抄（N68）。
   查到的數字是**要吃滿的預算，不是上限**；塞不下 `shoot.py` 會擋。
4. **不要用前置空白做縮排** —— SVG 會摺疊空白，縮排根本不生效；
   而且 `render_deck.py` 的翻譯查表會先 `strip()`，**帶空白的字串永遠對不到對照表**
   （上一版實跑踩過：三行文字在中文版全部沒翻到）。
   要縮排就調 `x` 座標。
5. **每個 `<text>` 要是一個完整的短句** —— 不要把一句話拆成靠縮排接續的兩三行。
   中英文的折行位置不同，拆過的句子換語言之後幾乎一定會斷錯地方。
6. **檔案節錄的樣式**（演示 agent 讀到什麼時用）：
   `.file` 外框 ＋ `.file-bar` 檔名列 ＋ `.file-name` ＋ `.file-line`，
   命中的那一行用**位置**（排最上面）或那一行的**金字**標出來 —— ⛔ 不用底色（6c）。
7. **圖裡的數字一樣要溯源** —— `check_deck.py` 會解析 `<text>` / `<tspan>` 的文字內容
   （只有文字，座標與尺寸不算）比對來源日誌。

## 改樣式

一律改 `assets/deck.css`，**一次改全部頁**。
⛔ 不要在 `deck.json` 裡寫樣式，也不要手改 `deck.en.html`／`deck.zh.html`（會被覆蓋）。

刻意跟投影片版面分開，這樣 `shoot.py` 的 raw 模式（播放器不啟動）看到的
就是**乾淨的 1600×900 版面**，量測不會被播放器影響。
改投影片長相 → `deck.css`；改播放操作 → `deck.js`。

### 總覽網格（`G`）對頁數的實務上限

播放器的總覽是 3 欄縮圖，一個 1280×720 的筆電螢幕**一次看得到 9 張**。
超過 **18 頁**就要捲動，而總覽存在的理由正是「教授問到剛剛那頁時馬上跳回去」——
要捲動就失去意義了。
現行頁數預算（主線 ≤15 頁、單線 ≤7 頁，backup 不計）本來就落在這個範圍內，
**這不是新的限制，是既有預算的另一個理由**。backup 頁很多時會超過，
但 backup 本來就是翻查用的，可以接受捲動。

⚠️ 新增版型時注意：slide 層級的 class 一律用 `t-<type>` 前綴
（`render_deck.py` 會自動加），內層元件才用裸名 `.cols`、`.stats`…。
不加前綴的話，`.cols{display:grid}` 這種規則會直接覆蓋掉 `.slide{display:flex}`，
整張投影片的排版會垮掉（上一版實跑踩過一次）。
