# 關係字彙與構圖清單（layer3 的執行規格）

> **這份取代「請 agent 畫圖」這個動詞。**
>
> 「畫圖」之所以做不好，是因為它把**四件性質不同的工作**壓成一個動作。
> 拆開之後只有第一件是 LLM 該做的：
>
> ```
> ① 關係抽取   ← LLM（語言工作，它擅長）
> ② 構圖選擇   ← 查表，不是想像
> ③ 填 JSON    ← LLM 填固定欄位（填空，不是創作）
> ④ 算座標渲染 ← code
> ```
>
> ⚠️ **現在有 renderer 的是這五個**（其餘構圖仍然手寫 SVG）：
> `read_pileup`、`haplotype_split`、**`chain`／`chain_gated`**（同一支；⛔ `chain_focus` 已廢除）、
> **`group_blocks`**、**`two_col_link`**。欄位契約見下方各段與「概念構圖的 spec 欄位契約」。
>
> 沒有 renderer 的構圖**仍要走完 ①②③ 的思考**，把構圖名與 JSON 寫進
> `slide.composition`，手寫的 SVG 照那份 JSON 畫。這樣之後補 renderer 時，
> 既有的頁不必重想，只要換掉渲染那一步。→ `BACKLOG.md`
>
> ⛔ **有 renderer 的構圖不准手寫 SVG。** 手算座標是「箭頭壓字、線對不到框、
> 同一張圖改四輪」的來源（實測），renderer 存在就是為了讓那件事不可能發生。

## Step ⓪ 守門：這頁該不該畫圖
<!-- @for: planner,builder -->

⚠️ 底下的四步流程**預設你已經決定要畫圖了** —— 它回答「畫成什麼」，不回答「該不該畫」。
少了這一關，每一頁都會被推去查表、查到一個構圖、然後畫出來
（實例：首次實跑那份 10 頁裡有 6 張手寫 SVG，全部平均用力，讀者看不出哪張才是主張）。

**預設是表格**。要離開這個預設，得先過三關：

1. **四個觸發訊號**至少中一個（兩個數字並排但不可比／數字之間的關係比數字本身重要／
   訊息的本質是時間或順序／多個項目擠在同一個狀態）。
2. **同尺寸測試**：把圖裡所有方塊改成一樣大、位置隨便排，意思有沒有變？
   沒變 → 那不是圖，是加了框的表格 → 退回 `table`。
3. **成本護欄**：一份 deck 最多 **2–3 張手繪**。已經有 3 張時，新的那張要先擠掉最弱的一張。

> 📄 三關的完整判準、反例與那個 6 張圖的實例 → **`diagram-craft.md §0`**。
> 這裡只放守門的存在與出口，不重複內容（避免同一事實寫兩處而分岔）。

過不了這一關 → 回 `table` 或文字版型，並把理由寫進 `why_text`。
過得了 → 往下走 Step ①。**手寫 SVG 的座標規則、marker、回圈邊、高度預算也在 `diagram-craft.md`。**

## Step ⓪b 路由：決定要畫了，先選**走哪條路**
<!-- @for: planner,builder -->

⚠️ Step ⓪ 決定「該不該畫」，這一關決定「**用哪個工具畫**」——少了它，每張圖都會直接
掉到最底下那格（手刻 SVG）。首次實跑那份 10 頁裡有 6 張手寫 SVG，代價是
**第三層的圖來回改了四輪**。**那是成本的結構性來源，不是缺工具**：我們一直有 CSS 版型
與 `render_figure.py`，只是沒有一條規則要人先去看它們。

> **由上往下選，能用上面那條就不要用下面那條** —— 越往下越要自己管座標，越容易畫壞。

| 圖長什麼樣 | 走哪條 | 讀哪份 |
|---|---|---|
| **單向線性流程**（A→B→C，可多 lane，節點內要放清單／數字／色塊） | **`pipeline` 版型**（純 CSS，不用管座標） | `slide_types.md` |
| **資料圖**：分佈、比例、覆蓋度這類**有數值**的 | `scripts/render_figure.py` 產 SVG | 本檔「領域構圖」與 `distribution` 段 |
| **有分支或判斷**，但排版單純上下左右 | ⚠️ **我們沒有 mermaid**，見下方「mermaid 那一格」 | — |
| 分支**回圈**要走特定路徑、節點裡要放 pill、要**精準控位** | 手刻 SVG | `diagram-craft.md` |
| 訊息本身靠**長度／位置／時間軸**編碼（誰比誰長、誰卡在哪一格、誰先誰後） | 手刻 inline SVG | `diagram-craft.md §0` |
| 抽不出關係／同尺寸測試沒過 | **退回表格或文字** | `diagram-craft.md §0` 三條自檢 |

⚠️ **第一格的限制要當真**：`pipeline` **只走單一方向**。一旦要分支或回圈就不要硬用它
（會得到一張「箭頭都對、但意思是錯的」圖），往下走一格。

### mermaid 那一格：我們**刻意留白**，不是忘了填

來源 skill 的第三格走 mermaid。我們**已評估並決定不裝**：

- 裝 `@mermaid-js/mermaid-cli` 會拉 **9 個直接依賴**（含 katex 數學排版、fontawesome
  整套圖示字型、zenuml）＋ peerDependency puppeteer（會**再下載一份 Chromium**，
  我們已經有 playwright 的那份）。對照現況：`package.json` 只有 **1 個**直接依賴、
  `node_modules` **7.9 MB**。
- weekly-deck 要推成實驗室公版，**多一道 `npm install` 就多一道門檻**。
- mermaid 產出的 `<text>` **不帶我們的用途 class**（`label`／`value`／`annot`／`def`），
  `check_purpose()` 會整片報錯，最後只能開豁免 —— **那個洞才剛補好**。

**所以這一格我們的路由是**：先問「**同尺寸測試過不過**」（`diagram-craft.md §0`）——
**過就手刻**（`diagram-craft.md`），**沒過就退回表格**。
分支圖多半只有三五個節點，手刻的座標成本本來就低；真正貴的是回圈與精準控位那一格。

⏳ 這個決定的**作廢條件**與重評估路線寫在 `BACKLOG.md` B12。

## Step ① 關係抽取（唯一的創作步驟）
<!-- @for: planner,builder -->

**不要問**「這頁該畫什麼圖」。**要問**：

> **這頁的 `point` 裡出現了哪些「有名字的東西」？它們兩兩之間是下列哪一種關係？**

名詞優先取 `plan.terms` 裡登記過的（見 `presentation_rules §1`「同一件事只准用一個名詞」）。

### 三個副產物（免費拿到的）

| 抽取的結果 | 代表什麼 | 該怎麼做 |
|---|---|---|
| 抽出**兩個以上不相干**的關係 | 這頁有兩個重點 | **拆頁**。這是「一頁一重點」第一次變成可偵測的 |
| **抽不出任何關係** | 這頁沒有圖可畫 | 正當退回 `table` 或文字版型，並把抽取結果寫進 `why_text` |
| 抽到**字彙以外**的關係 | 需要一個新構圖 | 標 `off_vocabulary: true` ＋ 寫 `why_off_vocabulary`，記進 `BACKLOG.md`；同一種出現第二次就升格 |

⛔ **不准為了套到現成構圖而改寫 `point`。** 內容決定構圖，不是反過來。

## Step ② 關係 → 構圖（查表）
<!-- @for: planner,builder -->

八種關係是**封閉字彙**，不准自創。同一種關係底下有多個構圖時，
**由 JSON 的判別欄位決定用哪一個，不由 agent 挑**。

### 1. `sequence` —— A 之後是 B 之後是 C

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `chain` | 每步等重、無分支 | `steps[]`，無 `focus` |
| ~~`chain_focus`~~ | ⛔ **已廢除**（6c 使用者裁決）——`focus` 唯一的作用就是把那一格塗成強調框 | `focus` 現在會直接報錯。要指出「看這一格」靠**標題**與該格內的**一處金字** |
| `chain_gated` | 步與步之間有關卡／驗收 | `steps[].gate` 有值 |

✅ **三個都有 renderer，而且是同一支**（`render_figure.py` 的 `render_chain`，
三個名字指到它）。理由：三者的幾何完全相同，差別只有「有沒有 `focus`」與
「`steps[].gate` 有沒有值」兩個**資料上看得出來的**布林 —— 正是本節說的
「由判別欄位決定，不由 agent 挑」。查表時照樣寫你要的那個名字，程式會自己認。
欄位契約見下方「概念構圖的 spec 欄位契約」。

> **守門提問**：**前一格的產出，是不是後一格的輸入？**
> 答不出來 → 這只是**時間順序**，不是流程。時間順序不要畫成箭頭鏈
> （把時間順序讀成因果是本 skill 記錄有案的失效，見 `editorial_policy §0`）。

⛔ 不准拿來畫：有分支或回圈的東西（改用 `correspondence` 或手寫）；
一週的工作按日期排開。

### 2. `transform` —— A 經過某個操作變成 B

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `transform_pair` | 一次轉換 | `from` / `op` / `to` |
| `transform_stack` | 同一個輸入被多種操作各轉一次 | `ops[]` 長度 > 1 |

✅ `transform_pair` **有 renderer**（`transform_stack` 還沒有）。

> **守門提問**：**那個「操作」叫什麼名字？** 講不出動詞（去重／過濾／混合／標記）
> 就不是 transform，多半只是兩個東西並排 → 改用 `compare`。

⛔ 不准拿來畫：前後對照但**兩邊不是同一個東西**（那是 `compare`）。
⚠️ `presentation_rules §1c` 已記載：前後對照只在**兩邊都是具體物件或數值**時才有用。

### 3. `partition` —— 整體拆成幾群

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `group_blocks` | 群裡的成員要一個個看見 | `groups[].members[]` 有內容 |
| `group_counts` | 只看每群幾個，成員不重要 | `groups[].n`，無 `members` |

✅ `group_blocks` **有 renderer**（`group_counts` 還沒有）。

> **守門提問**：**分群的依據是什麼？** 說不出依據就不是 partition，是清單。

⛔ `group_counts` 不准用來取代 `group_blocks`：
`presentation_rules §2c` 明訂「清單類直接 show 東西本身，不要只給統計」
（實例：20 個特徵要列出特徵名並用顏色分群，不是給「群｜個數｜這一群在看什麼」的表）。

### 4. `narrowing` —— 多 → 少，每一跳有判準

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `funnel` | 兩跳以內 | `stages[]` ≤ 3 |
| `funnel_named` | 篩完要點名剩下的是誰 | `stages[].survivors[]` 有值 |

✅ **兩個都有 renderer**（同一支，幾何相同）。

> **守門提問**：**每一跳的判準各是什麼？**
> 答不出來 → 這不是漏斗，只是數字變小，改用 `compare` 或表格。

⛔ 只給 `11 → 5 → 2` 不點名＝沒講（`presentation_rules §1c` 篩選類的固定講法：
原始清單 → 判準 → 結果，**三段都要**）。
⚠️ **面積要反映重點**：判準做成 block，數字框縮小（記錄有案的回饋）。

### 5. `compare` —— 幾個對象 × 幾個指標

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `bars` | 一個指標、多個對象 | `metrics[]` 長度 == 1 |
| `matrix` | 多指標 × 多對象 | `metrics[]` 長度 > 1 → 優先用 `table` 版型；<br>⚠️ **超過 table 容量上限（8 列 × 9 欄，唯一定義在 `check_deck.py` 的 `LIMITS`）就畫成網格 diagram**，不要硬塞（例：11 篇 × 6 步 = 66 格） |
| `before_after` | 只有兩個對象，且有時間先後 | `baseline` 有值 |

✅ `before_after` 與 `bars` **有 renderer**（`bars` 2026-09-06 補上；`matrix` 還沒有 → 用 `table` 版型）。
⭐ 一個框裡的小比較（兩三個數字）不必開整頁：用 `blocks` 的 glyph `bars`／`hero`（→ `glyphs.md`）。

> **守門提問**：**對照組是什麼？**
> 沒有對照組 = 這是清單不是比較。
> （`presentation_rules`：前後對照優先於單一數據——Baseline、修改前後、理論值 vs 實測值。）

⛔ 維度超過三個不要硬塞進一張圖。核心指標只留一個（`plan.terms.core_metric`
全程不換），其餘進 `notes` 口頭或 backup。**這件事要在 layer2 就擋掉，不是留到 layer3 想辦法畫。**

### 6. `containment` —— A 包含 B

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `nested` | 真的是包含（子集、子目錄、子集合） | `outer` / `inner[]` |
| `hub_spoke` | 一個中心連到數個週邊，**且都是直接連** | `center` / `spokes[]` |

> **守門提問**（`hub_spoke`）：**每根輻條都直接連到中心嗎？**
> 有兩層 → 那是樹不是 hub，改手寫或拆頁。

⛔ `hub_spoke` 不准拿來畫有先後順序的東西（那是 `sequence`）。

### 7. `correspondence` —— A 這邊每一項對到 B 那邊某一項

| 構圖 | 什麼時候 | 判別欄位 |
|---|---|---|
| `two_col_link` | 兩欄，之間連線 | `left[]` / `right[]` / `links[]` |
| `mapping_table` | 對應關係超過 6 組 | 用 `table` 版型，不畫線 |

✅ `two_col_link` **有 renderer**。⚠️ 它會在**放不下**時直接拒絕產圖並告訴你原因。
⭐ 判斷是**幾何的、而且是「或」**（N97）：兩欄共用 `1420 − 240（中間走道）= 1180px`，
按需求比例分配後**任一欄超出自己那份**就退出 —— 所以
**單邊過長就會被擋**（不必兩欄都是句子），而兩欄都是中等長度、總和沒破 1180px 則照樣產圖。
> 拒圖訊息給的正解仍是語意的：對應關係的兩端是**東西的名字**，
> 兩邊都是句子代表這其實是 `before_after`（上下疊）或該退回表格。
（首次實跑的 `writing_rules.svg` 標了 `two_col_link` 但 `links` 是空陣列，就是這種誤標。）

> **守門提問**：**有沒有對不到的？** 對不到的那幾個常常才是重點，要畫出來。

### 8. `distribution` —— 數值的分布或落點

> ⚠️ **這一種的 renderer 走 matplotlib → SVG**，跟前七種的幾何 renderer 分開
> （見 `BACKLOG.md`）。理由：分布圖要算 bin、算分位數，那是資料計算不是版面計算。

| 構圖 | 什麼時候 |
|---|---|
| `hist_overlap` | 兩群數值重疊多少（例：含腫瘤 vs 不含腫瘤） |
| `box_by_group` | 多群的分布擺一起 |
| `scatter_xy` | 兩個量的關係 |
| `line_trend` | 隨某個變因（TF、深度）變化 |

> **守門提問**：**這張圖上的門檻／目標線在哪？** 有門檻一定要畫出來並標數值
> （`log_schema.md` 的 SVG 約定）。

⛔ 不出 PNG。PNG 在 @2x 截圖下字會糊，而且 `render_deck.py --lang zh`
的字串替換掃不到 PNG 裡的字 → 中文版翻不到圖上的字。

## 概念構圖的 spec 欄位契約（有 renderer 的六個）
<!-- @for: builder -->

> 這裡寫的是**欄位契約**：哪些欄位可填、填了會發生什麼。
> ⛔ 不寫座標、不抄程式碼 —— 座標是 renderer 的事，你只填資料。
> 用法：`python3 scripts/render_figure.py spec.json -o figures/<name>.svg`
> （`spec.json` 就是 `slide.composition.spec`，第一個鍵是 `comp`）。
>
> 五條共同規則：
> · 圖寬固定 **1420**（⚠️ **兩個例外見下面的 N91 那段**）；
>   高由內容算，超過**這一頁的高度預算**會出聲警告
>   （圖會被等比縮小、字跟著變小）。
> · ⭐ **`budget` 是每一份 spec 的必填欄位**（N121）：數字去 `diagram-craft.md §6`
>   的表查（看這頁有沒有 `topic`／`sub`），查到幾就填幾 —— §6 仍是那個數字的
>   **唯一出處**，spec 只是**記下這一頁查到的是哪一格**。
>   ⛔ 舊版只能靠命令列 `--budget` 傳，於是「出貨時用的是哪個預算」
>   **沒有記在任何地方**，重跑的人只能猜。`--budget` 現在只是臨時覆寫。
> · ⭐ **出貨的圖必須重跑得出來**（`check_deck.check_spec_reproduces()`，**ERROR**）：
>   `render_figure.py <spec> -o <svg>` 重跑一次要**逐 byte** 重現出貨的那張圖。
>   ⛔ 判準不是「圖看起來一樣」—— N121 那 10 則字串幾何完全相同，看圖看不出來。
>   ⚠️ 這條同時擋住三件事：spec 留著佔位符、**手改了 SVG 沒回寫 spec**、
>   **spec 改了但圖沒重跑**。
> · ⭐ **一個 renderer 只有一支排法**，⛔ **不准依資料的形狀自動選排法**。
>   理由是實測的：`chain`／`group_blocks` 各有兩支自動選的排法，於是
>   **文件宣告的欄位在其中一支命中 0 次**且看程式碼與看圖都看不出來
>   （FINDINGS **N60**／**N92**／**N93**，三條同一個病）——
>   *寫 spec 的人選不了排法，所以他填的欄位會不會生效，他無從得知。*
>   ⚠️ 真的需要第二支時，用**明寫的 `layout` 欄位**選，⛔ 不由資料形狀推，
>   而且**每一個欄位在兩支排法裡都要真的被讀到**（交件前逐欄位 grep 命中次數）。
> · 每則文字的用途 class 由 renderer 給：節點名／清單／箭頭標籤＝`label`、數值＝`value`、
>   只有 `entry`（這張圖怎麼讀）是 `annot`。⚠️ `annot ≤2` 是**整張投影片**的額度，
>   所以一張圖最多用掉一則。
> · `tone` 一律吃**分類**語意值：`good`（保留／改善）／`bad`（問題／移除）／`null`（預期歸零）／`ctl`（控制變數）／不填。
>   ⭐ **不填不等於沒有顏色**（2026-09-05 起）：renderer 會自動配一個**區別色**
>   （`box-c1`~`c6`），⭐ 由**名字的雜湊**決定 → **同一個名字全 deck 同一個顏色**，
>   ⛔ 不必也不能在 spec 裡指定。它回答「這是並列的哪一個」，⛔ 不回答好壞。
>   明寫 `tone` 時**分類色永遠贏**。→ `presentation_rules §5`
> ⛔ **`hl` 已從形狀的 tone 移除**（6c）——形狀的顏色只做分類，不做強調。

#### ⚠️ 程式在讀、原本這張契約沒寫的欄位（N97）

這五項不是「進階用法」——**不知道就會踩到**，尤其那兩個預設值是 `true`：

| 欄位 | 行為 | ⚠️ |
|---|---|---|
| `steps[].num` | 覆寫 band 的自動編號；預設是 `"1"`、`"2"`…（位置推出來） | 填 `""` 可**整個關掉編號** |
| `groups[].members[].mono` | **預設 `true`** | 不是 opt-in：要一般字體得**明寫 `false`** |
| `two_col_link` 的 `left[].mono` | **預設 `true`**（左欄是名字，多半是識別碼） | 同上 |
| `two_col_link` 的 `right[].mono` | 預設**不是** `true`，不填＝一般字體 | ⛔ 左右兩欄預設相反，別憑印象 |
| `source.{tone,mono}`／`header.{tone,mono}` | 兩者都吃 `tone`（走 `TONE_BOX`）與 `mono`，不是只有 `{label}`／`{label,right}` | |

### box 內部的排版：`blocks`（可選，三個構圖共用）

> 為什麼有這一層（使用者裁決）：**block 的內部也要有明確設計** —— 不能只是開了框、
> 就把所有文字整段倒進去，框內要有明確的分隔與排版。
> 舊模型一個框只有 `lines: [str]`（扁平字串陣列）→ 性質不同的三組事實只能堆成一段被斷行的文章。
> `blocks` 是 `lines` 的**上位結構**：沒填就完全走舊路徑（既有圖逐位元組不變）。

```jsonc
"blocks": [
  { "head": "每項要寫的四件事",     // 小標，可省（省略時只靠分隔線分組）
    "tone": "bad",                  // 可省：分類色（good／bad／null／ctl）。⛔ 沒有 "hl"
    "pairs": [["question", "why today"], ["approach", "what was done"]] },
  { "head": "其他必填欄位", "lines": ["gaps · on every item"] },
  { "head": "上限與合併",   "numbered": ["cap 5 · no split ties"] }
],
"flow": "row"    // 子區塊並排（中間直分隔線）；"col" = 往下堆
```

- 四種內容**擇一**：`lines[str]`（純文字）／`pairs[[k,v]]`（key 與 value **各自對齊成欄**，
  ⛔ 不要再用 `·` 把兩件事串成一行）／`numbered[str]`（自動編號，編號進 pill 與內容分兩欄）／
  **`glyph`（小圖：點陣、分段條、read、探針…由數字畫，→ `glyphs.md`）**。
  一個 block 同時填兩種 → renderer **直接退出**（同 `rows`／`lines` 的作法）。
  ⭐ **框裡有數量、比例、座標、取捨 → 用 glyph，不用 pairs**（2026-09-06：九頁全是 pairs 的 deck
  與 APG 手繪 SVG 事實一樣多，看起來卻是「表格塞在框裡」）。
- `pairs` 的 term 欄寬 = **盒寬的固定比例**（0.32），gloss 從固定 gutter 起算，
  ⭐ **同一排／同一格線上的每個盒子共用同一個值** —— 跨子區塊、跨盒子都對齊。
  term 比配額長時 renderer 會讓開並**出聲**：正解是把 term 寫短（term 是**東西的名字**，
  不是句子），⛔ 不是去改比例。→ `diagram-craft.md §6b`
- ⭐ **有 `head` 的子區塊之間不畫線，靠空間分群**（群間 64 = 2 × 行內 32，
  鄰近律自己成立）；**只有沒有小標時**才畫 `.rule`。→ `diagram-craft.md §6b`
  只用既有 CSS 字彙（`label`／`hl`／`rule`／`pill`），
  每個 `<text>` 仍恰好一個用途 class，⛔ 不必動 `deck.css`。
- `flow` 寫在**放 blocks 的那個容器**上（chain 的 `steps[]`、group_blocks 的 `groups[]`／
  `members[]`、two_col_link 的 `left[]`／`right[]` 項）。
  ⚠️ **預設值不是同一個**：全寬的容器（chain `band` 的橫幅、group_blocks `rows` 的列）預設 `row`，
  窄框（chain `row` 的 1/n 欄、grid 的格子、two_col_link 的欄）預設 `col`。⛔ 不要憑印象填。
- 放不下（欄太窄）時 renderer **照樣產圖，但在圖底畫一條紅色 `RENDER OVERFLOW` 警示帶並說明改法**
（N94，批次 5g：舊版寫「拒絕產圖」而程式只印一行 stderr，回傳值也沒有人看 ——
stderr 在 subagent 流程裡最容易被吞掉；照 N95 的先例改成**看得見的紅帶**，
⛔ 不 `sys.exit`，否則一個過長的 value 會讓半成品 deck 整份渲染不出來），⛔ 不靜默截斷、不縮字級。
  另有一條提醒（不擋）：一格純文字超過幾行又完全沒有分組結構 → stderr 叫你改用 `blocks`。

#### ⛔ 高度預算的天花板（builder 最會踩的坑）

高仍受 **540** 約束，而 `blocks` 是**往上加**高度的 —— 超了 renderer 會把超出的數字印到
stderr 並給三個正解（改 `flow: "row"` ／ 減子項 ／ 拆頁）。兩個已知的硬上限：

- **`chain` band 4 格**：每格只剩約 **126px**（540 扣掉間距再除以 4）。子區塊往下堆一定爆。
  → 用預設的 `flow: "row"`：標題退到左欄、子區塊並排，**一個小標＋2 列**剛好裝滿。
  ⚠️ **那就是天花板** —— 要三組並排會撞欄寬，要更多內容只能減到 3 格或拆頁。
  ⚠️ 標題退左欄（省一整列）只在**這一格除了 `blocks` 什麼都沒有**時發生：
  同一格再填 `rows`／`lines`／含 `|` 的直欄群，子區塊就接到標題底下，預算立刻不夠。
- **`group_blocks` grid**：群裡子項多又要小標時，`value` 與 `sub` **不能同時保留**
  （兩者各吃一列，實測 10 子項＋3 小標就超過 540）。挑一個。

（門檻那種：條件在上、後果在下），這是省高度的關鍵。

| `groups[].mono` | 布林 | 成員用等寬字（特徵名、欄位名那種） |

| `layout` | `grid`／`rows` | 省略時由 `members` 的形狀決定 |

`rows` 的成員物件欄位：`name`（名字）／`desc`（一句它做什麼）／`right`＋`right2`
（右側兩行，例：角色與數量）／`tone`／`blocks`＋`flow`（那一列自己長高）。
**什麼時候會落到 `rows`**：一個成員要顯示三個以上的屬性時，格子裡塞不下。

### `two_col_link`

| 欄位 | 型別 | 意思 |
|---|---|---|
| `left[]` | 必填 | `{id, label, note, mono, tone, blocks, flow}`。`note` 排在名字右邊 |
| `right[]` | 必填 | `{id, label, tone, note, blocks, flow}` —— ⭐ **與左欄同一套算式**（FINDINGS N54 已解） |
| `links[]` | 陣列 | `[左id, 右id, tone?]`。**省略時 1:1 對位**；`tone` 套到兩端的框（分類色）。⛔ **金線已廢除（6c）** —— 「對不到的那幾條」靠**位置**（排在一起／排最上面）或**金字**講，不靠把線塗金 |
| `entry` | 字串 | 頂部整條的入口條件（唯一的 `annot`） |
| `footer` | 字串 | 右下角一行數值 |

> ⭐ **一個節點被多條連線提到時，tone 用 `or` 合併**：任一條線給了 tone 就套用。
> 理由：**「沒填」是「沒有意見」，不是「主張它是一般色」**，所以沒填的連線
> ⛔ 不該把別條線的主張洗掉。這也讓結果**與 `links` 的書寫順序無關**
> （書寫順序是資料順序，不該決定顏色）。
> ⚠️ **真正的矛盾**（同一個節點被一條線要求 `hl`、另一條要求 `bad`）
> **直接報錯退出**，⛔ 不靜默挑一個 —— 靜默挑一個正是舊版「後寫覆蓋前寫」的成因：
> 最後一條連線把某個節點的 tone 洗掉，左欄變成一格金一格藍，與 manifest 矛盾
> 且**改 deck 改不掉**（FINDINGS N35）。要單獨指定就寫節點自己的
> `left[].tone`／`right[].tone` —— **節點自己的 `tone` 優先於連線推出來的**。

⚠️ 欄寬**依內容算**，兩欄放不下時 renderer 會**拒絕產圖**並告訴你改用什麼。
⭐ **列高也是逐列算的**：填了 `blocks` 的那一列自己長高。
⚠️ FINDINGS **N54 已經不成立** —— 右欄原本連 `note` 都沒有、列高又寫死，
「每格多放一點事實」在右欄結構性做不到；現在左右同一套算式，沒填時 = 舊行為。

### `funnel` ／ `funnel_named`

> **一個 renderer 掛兩個名字**（幾何完全相同，差別只在 `stages[].survivors[]` 有沒有值
> ——**資料上看得出來**，符合「由判別欄位決定，不由 agent 挑」）。
> ⛔ 這不是「兩支排法」：`survivors` 只是某一段的內容多了一種，
> 每個欄位在**同一支**排法裡都會被讀到。

| 欄位 | 型別 | 意思 |
|---|---|---|
| `stages[]` | 必填 | **2–4 段**。⭐ 陣列順序就是**左 → 右**，框寬**逐段遞減** |
| `stages[].name` | 字串 | 這一段的名字（`label lead`）。⚠️ 只有 `survivors` 的那一段可以省 |
| `stages[].mono` | 布林 | 名字用等寬字 |
| `stages[].tone` | 字串 | 分類色（`good`／`bad`／`null`／`ctl`）。⛔ 沒有 `hl` |
| `stages[].value` | 字串 | 這一段的量（`label value`，字放大），畫在標題列右端 |
| `stages[].blocks[]` | 見上一節 | 段內子區塊（`flow` 固定 `"col"` —— 漏斗的段是窄框） |
| `stages[].lines[]` | 字串陣列 | 沒有 `blocks` 時的純文字 |
| `stages[].survivors[]` | 陣列 | ⭐ **`funnel_named` 的判別欄位**：這一段點名剩下的是誰。<br>每項 `{name, mono, tone, lines[], blocks[]}`，畫成**同 x 同寬**的一疊小框 |
| `stages[].criterion` | 物件 | ⭐ **進入下一段的判準**：`{name, mono, blocks[], lines[]}`。⛔ 最後一段不該有 |
| `entry` | 字串 | 頂部一行「這張圖怎麼讀」（整張圖**唯一**的 `annot`） |

#### ⭐ `criterion` **不畫框**，這是這支 renderer 最重要的一條

⚠️ 實測（`A3_selection_funnel.svg`，任務 4 之後）：框寬 **360 → 710 → 300×3**
—— ⛔ 不但沒變窄，還先變寬再分叉。**宣告了漏斗，畫出來是三欄清單。**
那個 710 就是判準：它被畫成一個**跟族群同樣分量的框**。

⭐ **漏斗的每一「段」是一個族群（多少東西還在），判準是「篩子」不是族群。**
所以判準只用 `label lead` ＋ 兩側各一條垂直 `.rule` ＋ 子區塊，**⛔ 不畫 `<rect>`**。
兩個效果，缺一不可：

1. **視覺**：讀者看到的是「兩個大小不同的族群，中間夾著一把篩子」，
   而不是三個並排的清單框。
2. **量尺**：`check_deck._stage_widths()` 只數方框 —— 判準畫成框就被算成一段，
   L4-1 的「寬度逐段不得變寬」立刻被自己的判準框否定。

⚠️ **判準要大是對的**（`presentation_rules`：「判準做成 block，數字框縮小」）——
不畫框**不等於**變小：`criterion` 欄拿的是它內容需要的寬，通常比任何一段都寬。

#### 座標（⛔ 唯一出處在這裡與 `diagram-craft.md §6b`，不要在程式裡另立數字）

- 欄序：`S1 · [C1] · S2 · [C2] · S3 …`，欄間距 `GAP = 4 × GRID = 32`，箭頭畫在間距正中。
- `criterion` 欄寬 = `clamp(_g8(_blocks_w(...)), 280, 720)`。
- 段欄寬：剩下的 `R = 1420 − Σ判準欄寬 − GAP × (欄數 − 1)`，
  依權重 `0.7^i` 攤到各段、`_g8` 之後**強制嚴格遞減**（每段至少比前一段窄 8px）。
  ⛔ 段寬下限 **240**；攤不出來就 `sys.exit` 並說明改法（減一段／把判準寫短／拆頁）。
- 每個段欄的框**垂直置中於圖的中線** —— 漏斗的收窄要看得出來。
  `survivors` 那一段是同 x 同寬的一疊框，間距 `GROUP / 2 = 32`，整疊置中。
- 箭頭：欄與欄之間各一支水平 `LINK()`；分岔到 `survivors` 時**每一個框各一支**。

### `transform_pair`

| 欄位 | 型別 | 意思 |
|---|---|---|
| `from` | 必填 | 轉換前。`{label, mono, tone, value, lines[], blocks[], flow}` |
| `op` | 必填 | ⭐ **那個「操作」的名字**（守門提問答不出動詞就不是 transform）。同一組欄位 |
| `to` | 必填 | 轉換後。同一組欄位 |
| `boundary` | 可省 | **不轉換的那一類**（邊界）。同一組欄位，排在 `to` 右邊 |
| `entry` | 字串 | 頂部一行（唯一的 `annot`） |

> ⭐ **四個容器同一套算式**（`two_col_link` 的 N54 已經踩過：右欄少了欄位，
> 「每格多放一點事實」在那一欄結構性做不到）。⛔ 不要給 `boundary` 少一組欄位。
> `flow` 預設 **`"row"`**（全寬容器，照上一節的共同契約）。

#### 座標

- `from` ／ `op` 由上而下各一條**全寬**橫幅（`x=0, w=1420`），之間一支**向下**的
  `LINK(710, y1, 710, y2)`。⭐ transform 的「變成」是有方向的，方向要畫得出來（L4-1）。
- `to`：沒有 `boundary` 時也是全寬；有 `boundary` 時
  `w_bd = clamp(_g8(需要的寬), 320, 560)`、`w_to = 1420 − w_bd − GAP`，
  ⭐ 兩者**同 y 同高**（共用水平軸）。
- 每條橫幅：`label lead` ＋ `.rule` ＋ 內容；`value` 有值時 `label value`
  畫在標題列右端（`anchor="end"`）。
- ⭐ **分類色靠 `from.tone` / `to.tone` 明寫**，⛔ renderer 不預設塗紅塗綠：
  「轉換前一定是壞的」不成立（照 `gate_tone` 的 opt-in 先例）。

### `before_after`

| 欄位 | 型別 | 意思 |
|---|---|---|
| `baseline` | 必填 | ⭐ **判別欄位**：對照組是什麼。畫在欄頭列最左（`annot`） |
| `rows[]` | 必填 | **2–4 列**，一列一個對象 |
| `rows[].name` | 字串 | 對象的名字（`label lead`） |
| `rows[].mono` | 布林 | 名字用等寬字 |
| `rows[].tone` | 字串 | 這一列的分類色。⛔ 沒有 `hl` |
| `rows[].before` `rows[].after` | 字串 | 前後兩個值（`label value`），中間一個 `→` |
| `rows[].delta` | 字串 | 差額（`label value`）。可省 |
| `rows[].hl` | `before`／`after`／`delta` | ⭐ 這一列哪一格上**實心金**（`value hl`）。可省 |
| `rows[].blocks[]` `rows[].flow` | 見上一節 | 列的右半：為什麼會這樣（`flow` 預設 `"row"`） |
| `rows[].lines[]` | 字串陣列 | 沒有 `blocks` 時的右半純文字 |
| `before_label` `after_label` | 字串 | 欄頭。預設 `"before"`／`"after"` |
| `before_tone` `after_tone` | 字串 | ⭐ **這一欄的分類色**（`bad`／`good`／`null`／`ctl`）。⛔ opt-in，renderer 不預設塗色 |

#### ⭐ 共用軸是**真的**共用，⛔ 不是三條並排的橫幅

L4-1 的 `compare` 要「≥ 2 個方框的 `(x, w)` 相同」—— 三條全寬橫幅**自動就過**，
⚠️ 那等於這條量尺對 `before_after` 沒有作用。所以這支 renderer 要的是**兩件都做到**：

- 列框全寬同寬（`x=0, w=1420`）→ 過 L4-1；
- ⭐ **而且 `before`／`after`／`delta` 三欄的 x 在每一列都是同一組值**
  （`X_BEFORE` ／ `X_AFTER` ／ `X_DELTA` 全圖各一個），
  ⛔ **不逐列各自算** —— 逐列各自算就是「表格最基本的失效」，
  跟 `_col_x()` 與 `_term_w()` 擋的是同一件事。
  ⭐ 觀眾能不能「比」，靠的是這一組 x，不是那三個框。

#### ⭐ 分類色掛在**欄**上，⛔ 不是掛在列上

`before_after` 的分類軸是 **舊 vs 新**，⭐ 那是**兩欄**的差別 ——
而 `presentation_rules §5` 的字面就是 `box-bad`＝**舊的**、`box-good`＝**新的**，
⛔ 不是我們另外發明的用法。所以：

```jsonc
"before_tone": "bad",   // 舊的那一欄
"after_tone":  "good"   // 新的那一欄
```

⛔ **不要改用 `rows[].tone` 來做這件事。** 並列的三列講的是同一件改動的三個面向，
⭐ **是同一類** —— 逐列上色就是「並列的同類裡標一半」，
正是 6c 使用者點名要拿掉的雜訊（§5：「並列的東西標一半 = 雜訊」）。
⭐ 欄級上色則是不折不扣的**分類**：整欄同色，回答「這一欄是舊的還是新的」。

⚠️ **opt-in，⛔ renderer 不預設塗紅塗綠**（照 `steps[].gate_tone` 的先例，N34）——
有些 `before_after` 的 before 只是**基準**，不是缺陷。

⭐ **順帶讓第 6、7 頁用同一個裝置**：`transform_pair` 的 `from.tone: "bad"` ／
`to.tone: "good"` 與這裡是同一組語意，跨頁一致。

#### 座標

- 欄頭列（**不畫框**）：`baseline` 在最左（`annot`），
  `before_label` ／ `after_label` 對齊 `X_BEFORE` ／ `X_AFTER`（`label section`）。
- 每列一個全寬 `box`（同 `w`、同 `h`），列間距 `GROUP / 4 = 16`。
- 列內：`name`（`label lead`）＋ `.rule` ＋ 左半數值列 ＋ 右半 `blocks`。
- 有 `before_tone`／`after_tone` 時，那一欄的數值後面墊一個 `LEAD`(48) 高的色塊，
  ⭐ **貼著數值那一行**，⛔ 不是整列高（整列高會變成大半是空的色塊，
  數值反而縮在最上緣 —— 實測過）。色塊會蓋掉 `.rule` 的一段，⭐ **那是對的**：
  有色塊的地方不需要再畫一條線分隔（同 §6b「有小標就不畫線」的道理）。
  右半起點 `X_BLOCK = _g8(1420 × 0.535)`，⭐ **全圖一個值**。
- ⛔ 一張圖的實心金（`rows[].hl`）由 `layout_reviewer 3c` 管上限，
  renderer **不擋也不補**（`diagram-craft §6c`：上限 1、⛔ 沒有下限）。

## Step ③ 把構圖寫進 slide
<!-- @for: builder -->

不論最後是 renderer 產的還是手寫的，**都要留下這一段**：

```jsonc
"composition": {
  // ── layer2（slide_planner）填 ──
  "relation": "narrowing",          // 八種關係之一，或 "domain"
  "comp": "funnel_named",           // 構圖名
  "gate": "每一跳的判準：① 有沒有做 read 層去噪 ② 用的是不是純軟體手段",
                                    // ★ 守門提問的答案。答不出來就不准用這個構圖
  "spec_hint": "三跳 11→5→2，判準做成 block 放右側且面積要大於數字框",
                                    // 要放什麼內容、哪一群用重點色。**不含座標**
  "off_vocabulary": false,          // 見下

  // ── layer3（slide_builder）填 ──
  "spec": { /* 該構圖的 JSON，含座標級細節 */ },
  "handwritten": true               // 這張圖是手寫 SVG（沒有 renderer 可用）
}
```

### ⚠️ `handwritten` 與 `off_vocabulary` 是兩件事，不要混用

受控演練時這兩個概念寫成同一個欄位，結果 6 頁裡有 4 頁得寫一句
「構圖在字彙內、只是沒有 renderer」的理由——那對 `BACKLOG.md` 是純雜訊。

| 欄位 | 意思 | 要不要寫理由 | 進 BACKLOG？ |
|---|---|---|---|
| `handwritten: true` | **沒有 renderer**，這張圖用手寫 SVG 畫 | ❌ 不用。第一批只有 2 個 renderer，**這是常態** | ❌ |
| `off_vocabulary: true` | **關係或構圖在字彙之外**，八種關係都套不上 | ✅ 要寫 `why_off_vocabulary`：為什麼現有構圖都不適用，並提一個候選構圖名 | ✅ **同一種出現第二次就升格** |

⛔ 兩者互相獨立：字彙內的構圖現在幾乎全部 `handwritten: true` 而 `off_vocabulary: false`。

## ⭐ Step ④ 宣告的關係要**看得見**（L4-1，`check_deck.check_relation_evidence`）
<!-- @for: builder,reviewer -->

> ⭐ **構圖宣告了什麼關係，就必須看得到那個關係。**
> 宣告與畫面互相否定時吃虧的是觀眾 —— 他讀到的是圖，不是 JSON。

**這是 ERROR，不是建議。** 每種關係的「看得見」定義（⛔ 唯一出處，程式照這張表寫）：

| `relation` | 圖上必須有 | 怎麼量（推導自 SVG） |
|---|---|---|
| `sequence` | **方向記號** | `.arrow` ≥ 1 **或** 編號 ≥ 2（`^\d+ —` 開頭的 `<text>`，或 `.num`） |
| `narrowing` | **寬度遞減** | 方框依 x 分欄（40px 容差），每欄代表寬度**逐段不得變寬**（+8px 容差） |
| `compare` | **共用軸** | ≥ 2 個方框的 `(x, w)` 相同（同垂直軸）或 `(y, h)` 相同（同水平軸） |
| `correspondence` | **連線** | `.arrow` ≥ 1 |
| `partition` | **≥ 2 個群容器** | `grp`／`box` ≥ 2 |
| `transform` | **前後看得出來** | 有分類色（`box-bad`／`good`／`null`／`ctl`）**或** `.arrow` ≥ 1 |

### ⚠️ `sequence` 的方向記號**包含編號**，⛔ 不是只認箭頭

`_chain_band()`（全寬橫幅）的設計就是「**順序靠編號不靠箭頭**」——
橫幅上下相疊，中間沒有畫箭頭的間隙。實測 `A2_scan_chain.svg` 箭頭 0 個，
但三條橫幅是 `1 — …`／`2 — …`／`3 — …`，⭐ **它有方向，只是用編號**。

⛔ **只認箭頭 = 逼 renderer 在自己刻意不留的位置上硬塞記號**。
⭐ 這與 6c 那條「一頁金色下限是 1」是同一種錯：**規則否定自己的產物時，錯的是規則。**

### 具名豁免

manifest 的 figure 條目可寫：

```jsonc
"relation_exempt": {
  "reason": "為什麼現在畫不出來（⛔ 留白不算豁免，照樣 ERROR）",
  "until":  "什麼條件成立就把這條拿掉"
}
```

⚠️ 每一條豁免都會發 **WARN**，⭐ **債務是吵的，規則對其他人是硬的**。

## ⭐ Step ⑤ 同一個東西每頁長得一樣（L4-2，`check_deck.check_object_consistency`）
<!-- @for: builder,reviewer -->

⭐ **跨頁不一致是「精細度」感受的最大殺手 —— 觀眾會以為那是不同的東西。**

### ⭐ 外觀是**推導**的，⛔ 不是宣告的

⛔ **`objects` 的 value 維持一句散文，不要改成 `{shape, color, pos}` 三個欄位。**
裁決記錄與實測見 `FINDINGS.md` **N123**，兩個致命理由：

1. **比對宣告 ≠ 比對畫面** —— 兩頁都宣告 `shape:"box"` 就過關，而 SVG 裡一個是
   `grp` 一個是 `box` 也照樣過。⭐ **檢查可以靠改帳本滿足，不必改圖**，那是裝飾。
2. **它是同一個事實的第二份手抄本，而手抄本一定會漂**（N14 記過同型的）。

三件外觀事實**全部推得出來**（⭐ 是 6a／L0 把 class 收斂成單一來源之後才可能的）：
**顏色角色** ← `<text>` 的 class；**形狀** ← 包住它的最小 `<rect>` 的 class；
**位置** ← `x`／`y`。

### 帳本只宣告**推不出來的那一件**：身分

「A3 的 `daily · .html` 跟 A1 的 `daily · .html · .md` 是同一個東西」——
那是語意，字串比對永遠追不到。所以 `shared_terms` 的 value 升級成物件：

```jsonc
"shared_terms": {
  "daily · .html": {
    "why": "呈現層那一份的真名",                      // 原本的散文，保留
    "aka": { "A1": "daily · .html · .md",             // ⭐ 同一個東西在各頁的實際字串
             "A3": "daily · .html" },
    "role_exempt": { "A3": "A1 是成員群（grp），A3 是漏斗終點框（box）——"
                           "容器不同是刻意的（⛔ 必須寫理由，留白不算豁免）" }
  }
}
```

⭐ **向下相容**：value 是**字串** = 舊寫法，照舊認、⛔ 不報錯。

### ⭐ 「長相」只看**標題型**出現，⛔ 不看引用

物件的長相 = 它**被介紹**的那一則（`lead`／`section`）。
其餘（`gloss`／`value`／`term`／一般 `label`）是**指到它的引用**，⛔ 不比。

> **為什麼**：第一版把所有出現都拿來比，量到 3 組不一致，**其中 2 組是誤判** ——
> `candidates.py` 在 A1／A3 是框名（`lead`）、在 A2 是 key/value 列的 value（`gloss`），
> 那不是「長得不一樣」，那是**同一個東西被引用到**。收斂後剩 1 組真發現。

⚠️ **< 4 字元的字串不比對** —— ⛔ N111② 已經在 `check_manifest` 踩過一模一樣的坑
（`10`、`x` 這種對誰都命中，等於沒檢查）。

## 這份字彙怎麼長大
<!-- @for: builder -->

1. **同一種「字彙外的關係」出現兩次** → 升格成第九種關係，或某關係下的新構圖。
2. **同一個構圖連續兩週被使用者指出看不出在講什麼** → 不是內容問題，是構圖不對，
   回頭改守門提問（它讓不該用的情況溜進來了）。
3. 新增構圖要**同時**補三樣：判別欄位、守門提問、⛔ 反例。
   只加名字不加守門提問等於沒加——那正是「硬套」的來源。

> ⚠️ 別忘了 `presentation_rules §4` 的已知偏差：**規劃者會系統性選到表格**（表格是零成本預設）。
> 但也不要過度矯正——用那把尺回頭量一份 8 頁的舊週報，真正該換成圖的只有 1 頁。
