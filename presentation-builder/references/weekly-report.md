# Weekly Report

進度報告 / 週報的內容規則。做法（頁面、build、匯出）見主 `SKILL.md`；這裡只講
**內容與版面規則**，與哪種引擎無關。

本 reference 只適用週報。週報一週一個日期目錄，日期固定為當週週五；`daily-work-log` 的日報
另行使用每天一個來源日期目錄，不套用本文件的週五規則。

---

## 報告目錄與命名

- 新建週報資料夾一律命名 `YYYYMMDD-w`（`create_folder.sh` 產生，放在 `REPORT_ROOT` 下，例如
  `${REPORT_ROOT}/20260828-w/`）。`-w` 明確區分同日的日報；既有純日期或帶前綴資料夾照樣支援 build，
  但不重新命名。
- **資料夾後綴不改變報告名稱，但週報匯出會附上目前 OS 使用者名**。新建 `YYYYMMDD-w` 資料夾
  預設匯出為 `進度報告YYYYMMDD-<使用者名>`；例如 jerry 建立 `20260515-w/` →
  `進度報告20260515-jerry.pptx`。要別的名字仍可用 `--name`；舊有純日期資料夾的匯出行為維持不變。
- 每頁一個 `NN-slug.html`（`NN` 兩位數決定順序），`build.py` 彙整成 `deck.html`。
- **日期慣例**：週報預設每週五發表，日期就是**當週週五**。若使用者明確指定本次報告日期，
  指定日期優先；不要以執行環境的今天或下一個週五覆蓋它。未指定日期時，才自動算出當週週五。
  例：2026-05-13（週三）製作 → 週五 2026-05-15 → 資料夾 `20260515-w/`，匯出
  `進度報告20260515-jerry.pptx`（使用者名依執行帳號變動）。
- 開工前先確認是否已有進行中的報告（`ls` 該資料夾）；**已存在就直接續編，不要重跑會清空的步驟**。

### 標準封面

封面由 builder 產生，不要自行建立 `01-cover.html` 或另寫一張相似封面：

```bash
python ~/.codex/skills/presentation-builder/build.py \
  "${REPORT_ROOT}/YYYYMMDD-w" \
  --date YYYYMMDD --titlecover
```

標準封面固定顯示「進度報告、週報日期、報告者」。builder 會自動驗證封面內容、
資料夾日期、頁面 marker 與最終頁數；若不一致會停止產出流程並回報錯誤。

## 數字怎麼放

判準一句話：**改一個來源數字，頁面上跟它有關的數字會不會一起變？**
會就沒問題，不會就要處理——跟它寫在哪裡無關。下面三類只是這句話的展開。

| 類別 | 例子 | 做法 |
|---|---|---|
| **量測值 / 查詢結果** | DB 查詢、PubMed 命中數、列數、樣本數 | 放 `data/` 的 TSV/CSV，頁面讀出來渲染。寫死最容易出事：資料一更新就對不上，而且沒人會發現 |
| **衍生值** | 百分比、倍數、效果量、單位換算 | 由產頁程式**從量測值算**。不要把算好的結果存進 data——存了算式就消失，來源一改它不會跟著變 |
| **常數 / 識別字** | errno、型別上限、欄位門檻、版本號 | **可以直接寫在頁面**。這類不會因為重跑資料而變，塞進 TSV 只是多一層 indirection；但頁面上要找得到出處（程式碼路徑或規格名稱） |

兩個容易漏掉的地方：

- **不是只有表格**。`lead` 那句、`.info-card` 內文、`.takeaway` 裡的數字一樣算數，
  而且比表格更常跟資料脫節。同一個數字出現在多處時，讓它們來自同一個變數。
- **同一張表不要混不同時間的查詢**。PubMed / DB 的數字每天在動，補一列就把整批重查，
  或分開標日期；否則那張表不能拿來比較。

**什麼時候值得寫產生器**：頁面上的量測值超過五個，或同一個數字出現在兩處以上。
少量數字的頁面手寫、圖說註明出處就夠了，不用為了三列的小表寫腳本。

> 這條原本寫成「不在 HTML 手打數字」，是因為舊引擎的表格本來就由 JS 讀 TSV 渲染，
> 那句話在描述機制。換成現在的靜態頁 + builder 之後機制沒了，只留下禁令，
> 於是既擋不住真正會出錯的地方（衍生值、跨區塊不一致），又把 errno、規格常數
> 這種寫死也無妨的東西一起管進來。改成上面的判準是為了回到原意。

## 內容規則（硬性）

- **表格資料來源必須是 apgpas-query 查詢輸出或系統 TSV**，不可自行組造或改寫數字與文字。
- **物種名稱嚴禁縮寫**（例：不可把 *Lachnoanaerobaculum sanguinis* 縮成 *L. sanguinis*）；
  屬名完整保留以免歧義。
- 允許對特定 cell / 欄位加 inline CSS（紅字、粗體等）調樣式，但**不得改動 cell 文字內容**。

## 文字與視覺密度

- 每頁正文（標題、說明、卡片與結論合計）控制在約 **50 字內**；週報也是講者提示，不是講稿。
- 以一個流程、圖表、前後比較或關鍵數字作為主視覺，細節由講者口頭說明。
- 一頁只講一個重點，通常每個事項 1–2 頁即可；不要用長段落或密集表格塞滿頁面。
- 週報不套用月會專用的「痛點 → 改善」公式；可依技術事項採用問題、進度、結果、決策或下一步等結構。

## Issue 頁內容規則

- **問題頁必須附上展示問題的真實 case 表格**（純文字無法讓與會者快速理解）。標準結構：
  1. 1–2 行說明問題根因
  2. 表格：有問題的真實 case 資料
- 常見表格欄位（依 issue 性質選）：
  - cojudger pathogen 排除/降階 → `patient_id`、`organism`、`genus`、`mclass`（before）、期望結果（after）
  - autojudge 判斷錯誤 → `chip_id`、`specimen_id`、`seq_id`、`organism`、autojudge result、期望結果
  - 報告輸出異常 → 直接貼出問題輸出欄位

### 檢體基礎資訊（case 表必附，不可省略）

只要頁面在列個案（case 表、before/after 檢體清單），除了分析欄位，**這五項一定要看得到**：

| 項目 | 來源欄位 | 寫法 |
|---|---|---|
| 檢體代碼 | `specimen_submission.specimen_id` | 原樣 |
| 檢體類型 | `specimen_submission.specimen_type` | tissue 要把器官寫進去：**`tissue ($organ_source)`**，例如 `tissue (lung)`；`organ_source` 為空才只寫 `tissue` |
| 醫院 | `specimen_submission.hospital` | 原樣，不縮寫 |
| 部門 | `specimen_submission.department` | 原樣 |
| 醫生 | `specimen_submission.doctor` | 原樣 |

沒有這些，看報告的人無法判斷個案的臨床脈絡，也就沒辦法討論。

**整批相同時放表格上方一行，不要佔掉每一列的欄寬**：同一張晶片的個案常常同醫院、
同醫生，這時把「醫院 X｜部門 Y｜醫生 Z」寫成表格上方的一條資訊列，表格只留
`specimen_id` 與檢體類型；有兩個以上不同值時才展開成欄位。判斷方式是取該欄的
unique 值，只有一個就提上去。
- **不放的工程細節**：版本號、MR/PR 編號、Deployment/CI 狀態、unit test 數量。
- **要放的**：修正邏輯的技術說明（例如「per-patient 排序後，每個 genus 群組把第二名以後降為排除」）
  以及關鍵程式碼片段——這些是報告重點。

> 原則：不放版本/MR/CI 等管理資訊，但修正邏輯的技術說明與程式碼要呈現。

## 截圖版面自檢（寫頁面前先評估）

PPTX 匯出是用 html2canvas **截圖**每頁（不滾動），所以**所有內容必須在初始 render 就完整可見**，
被 overflow 截斷的內容不會進 PPTX。加頁前用以下原則自檢：

| 檢查 | 判斷 |
|---|---|
| 表格欄位數 | > 5 欄要縮小字體（`font-size: clamp(7px,0.8vw,11px)`）或減欄 |
| 欄位內容長度 | endpoint 路徑、datetime 等長字串估算是否撐爆欄寬；可合併欄（old→new）或截短 |
| 多區塊並排 | 左右欄各塊超過 5 條 bullet 或 8 行表格時，改上下疊 |
| overflow | 截圖不滾動；超出部分用 `overflow: hidden`，不要 `auto` |

**原則**：看欄位數與最長欄位值，腦中估算能否排進 16:9；不確定就主動縮字體或改上下版型。
版型與語意 class 見主 `SKILL.md`。

## 分析型 issue 頁

issue 頁的證據若是自己跑資料畫出來的圖（覆蓋圖、pileup、序列結構示意），
先讀 `references/figures.md`：canvas 尺寸、圖表誠實性自檢、數字出處與詞彙規則。

兩條最常被提出的意見：

- **數字要有出處，但不要獨立開一頁講出處**——寫在圖說和 `.info-card` 裡，跟著數字走
- **不要突然冒出新詞彙或未定義的符號**（`n=726`）；中文報告就寫「726 條」
