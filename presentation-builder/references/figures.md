# 自製圖表（SVG / 腳本產圖）

流程／示意圖見 `diagram-mermaid.md` 或 `diagram-svg.md`，截圖見主 `SKILL.md` 的版型章節。
這裡只講**自己寫腳本產出的資料圖**（覆蓋度、pileup、比例分佈）——分析型報告最常用，
也最容易在「圖看起來很正常但結論是錯的」這件事上翻車。

---

## 1. 尺寸：先算可用寬度，再決定 canvas

投影片是 1280 × 720。扣掉 padding 後的可用寬度：

| padding | 可用寬 |
|---|---|
| `52px 60px 40px` | 1160 |
| `28px 40px 20px` | 1200 |
| `20px 36px 16px` | 1208 |

**滿版圖的 SVG canvas 寬度直接設 1180**，不要用預設的 800/900——`object-fit:contain`
會把小圖縮在中間，四周留一圈白，看起來就是「這麼大的空間圖卻很小」。

`<img>` 的 `max-height` 要**貼合 SVG 自身的長寬比**：

```
max-height ≈ SVG height × (實際顯示寬 / SVG width)
```

canvas 1180×470 放在可用寬 1208 的頁面 → `max-height:470px` 左右。設太大不會變大
（受寬度限制），設太小會被裁；兩者都會產生多餘留白。**改完 canvas 尺寸就要回頭改
`max-height`**，這兩個數字是綁在一起的。

**SVG 根標籤一定要加 `width`/`height`，只有 `viewBox` 不夠**：

```xml
<svg viewBox="0 0 1180 470" width="1180" height="470" xmlns="...">
```

單頁瀏覽器預覽沒事，因為版面是用 CSS（`max-width`/`max-height`/`object-fit:contain`）
控制顯示尺寸，`width`/`height` 屬性不影響那個結果。**匯出 PPTX 才會爆炸**：`deck.js`
的 `renderSlideToCanvas()` 用 `html2canvas` 截圖，但 html2canvas 不支援 `object-fit`，
所以匯出前會先讀 `img.naturalWidth`/`naturalHeight` 自己算等比例縮放。只有 `viewBox`
沒有 `width`/`height` 的 SVG，`naturalWidth`/`naturalHeight` 是不可靠的 intrinsic size
（不同瀏覽器算法不一致，常常跟 `viewBox` 對不上），縮放公式吃到錯的值，圖片就會被
放大到跑出投影片範圍——而且這個問題在單頁預覽或改版面時完全看不出來，只有實際匯出
PPTX 才會現形。**產圖腳本輸出 SVG 時，`width`/`height` 屬性要跟 `viewBox` 的寬高一致**，
手動修圖也一樣，別只補 `viewBox`。

## 2. 產圖流程

- 產圖腳本放在**分析工作目錄**（跟資料在一起），不要放進報告資料夾
- 腳本輸出 SVG 後 `cp` 到 `<報告目錄>/data/`
- 要改圖就**改腳本重跑**，不要手改 SVG——手改的版本下次重跑就沒了
- 腳本開頭寫一段 docstring 說明這張圖要回答什麼問題，以及**資料是怎麼篩的**

## 3. 圖表誠實性自檢（畫完必跑）

排版錯誤看得出來，這類錯誤看不出來——圖面完全正常，但結論是錯的。

| 檢查 | 為什麼 |
|---|---|
| **篩選條件會不會剛好濾掉關鍵證據？** | 最危險的一種。逐條寫出每個 filter，問「被濾掉的那群，會不會正是要找的東西」 |
| **有沒有把異質的東西平均成一個數字？** | 一段序列若一半 100% 相同、一半完全不存在，「平均 75%」誰都不是。分開畫，不要平均 |
| **軸標籤講的是「什麼」還是「哪裡」？** | 「這段存在嗎」和「這段在同一位置嗎」是兩回事，標籤沒寫清楚就會被誤讀 |
| **多重比對的區域，深度是真的還是被攤平的？** | 相同拷貝上 aligner 隨機分配，各拷貝深度一致不代表各拷貝都有訊號 |
| **邊界被截斷的資料有沒有畫出來？** | 只畫「完整落在視窗內」的元素，等於把跨界證據藏起來。視窗要比資料範圍寬 |
| **對照組在同一張圖上嗎？** | 陰性/正常樣本並排，讀者才知道觀察到的形狀是不是特別 |

被篩掉的資料量若超過一成，就在圖說寫出來（篩掉幾筆、依據是什麼）。

## 4. 數字出處

使用者常問「這個數字哪來的」。做法：

- **出處寫在圖說與 `.info-card` 裡**，跟著數字走
- **不要為了交代數字獨立開一頁**——會顯得刻意，也打斷敘事
- 分清楚 **pipeline 輸出** 與 **本機重跑**，兩者不可混用；本機重跑要註明參數
- 用**完整的數字鏈**取代單一數字：`6,657,860 → 452 → 449 → 265` 比「449 條」清楚

## 5. 詞彙

- **不要引入未定義的符號或簡寫**（`n=726` 這種）。中文報告就寫「726 條」
- 一個概念從頭到尾用同一個詞；換詞就等於換概念
- 圖上出現的每個名詞，頁面上要找得到它的定義或來源

## 一頁一個主張

標題就是那個主張的一句話陳述，圖是它的證據，卡片是佐證細節。
一頁講不完就拆頁，不要把兩個主張塞進同一張圖。
