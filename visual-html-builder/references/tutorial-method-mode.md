# 研究方法教學模式

本模式只用於論文方法導讀、研究流程教學、實驗室 tutorial 或教授報告輔助。一般儀表板與資料分析頁仍遵循主 skill 的既有規範。

## 敘事優先順序

1. 先用一句白話說明方法要解決的問題。
2. 再交代輸入、處理、判斷依據與輸出。
3. 最後才補工具名稱、演算法名稱、程式模組或實作位置。

程式碼、README 與設定檔主要用來確認方法如何實作，不直接當成主要講稿。若必須顯示程式資訊，放在「實作對照」或摺疊補充區，並先說明它代表的概念。

首次出現的專有名詞需同時提供：中文白話定義、它在流程中的角色，以及一個短例子。不要只用另一個術語解釋術語。

整份頁面依「先有因，再有方法，最後才有結果」排序。研究發現若是方法出現的起因，先交代該發現或量測困難，再說明方法如何解決；不要先展示結論，之後才補原因。教授報告可採：研究背景與問題 → 為何需要此方法 → 原始資料與輸入 → 核心處理 → 如何選答案 → 輸出 → 研究發現 → 限制。

## 原始資料與方法連結

- 不能只列工具名稱。畫出資料血緣：最原始資料 → 必要前處理 → 中間檔或訊號 → 方法實際輸入 → 方法內部步驟 → 最終輸出。
- 清楚區分「原始資料」、「上游工具輸出」與「核心方法內部步驟」。上游 caller、annotation 或 normalization 工具不得誤畫成核心方法本身。
- 每一種輸入都回答兩件事：它從哪裡來，以及它限制或判斷什麼。若四種輸入提供互補證據，使用平行圖卡或泳道後再匯入核心方法。
- 流程圖每一步只保留一個動作與一個產物，例如「找訊號跳變處 → 得到穩定區段」；詳細定義放在鄰近圖例，不把整段方法文字塞進節點。
- 「訊號轉折」、「候選評分」、「一致性」等抽象詞必須改寫成可觀察的動作。例如：數值突然跳高或降低、把候選預測拿回觀察資料驗算、對不上就加罰分。
- 將「已知觀察值」、「候選假設」與「模型輸出」視覺上分開。原始讀序、帶座標讀序、讀取量比值、等位基因比例與 AD／DP 可列為觀察資料；腫瘤純度、倍性、DNA 份數、突變份數等若由模型估計，不得寫成原始資料已知。
- 若上游工具平行運作，畫成獨立泳道並標明匯合點；同時註明每項結果在哪個核心步驟真正被使用。不得因兩條上游管線獨立就暗示它們分別估計兩套最終答案。
- 分段流程需區分「連續數值經演算法找出的候選邊界」與「外部 caller 直接提供的事件座標」，並交代邊界合併、距離過濾、強制邊界及區段代表值等實際規則；若只掌握概念，不自行補出實作細節。
- 論文管線與目前軟體實作不一致時，主圖以使用者要報告的版本為準，工具卡旁用小字標示另一版本。不得把目前工具名稱回填成舊論文當年的方法。
- 使用「程式碼就是這樣做嗎」之類的實作主張時，必須查官方原始碼或官方演算法文件；只查到 README 時，明說驗證層級是官方文件而非逐行程式碼審計。

## 方法頁必要結構

頁面至少清楚回答以下問題：

- 問題：這個方法想估計、分類或校正什麼？
- Input：方法實際吃進哪些資料？每種資料提供什麼證據？
- Process：資料經過哪些步驟？每一步做什麼判斷？
- Evidence：不同訊號如何互相限制、交叉驗證或消除歧義？
- Output：最後輸出哪些數值、類別、圖或檔案？如何解讀？
- Limits：何時可能不可靠？需要哪些品質條件？

流程圖以 Input → Process → Output 為主骨架。每個步驟使用動詞標題，箭頭必須表達真實的資料流或依賴關係，不能只為裝飾。複雜方法可再展開成「輸入 → 特徵／證據 → 候選模型 → 評分或一致性檢查 → 最佳解 → 輸出」。

## 視覺與教學例子

- 採研究室教學頁的內容優先風格：淺色背景、寬鬆留白、清楚的編號章節、細緻分隔線與直接標註。
- 使用者指定的主色優先。若未指定，採中性色加單一強調色；若指定紫色，紫色作為唯一主色，搭配深紫文字與淡紫底色。
- 導覽列、側欄或進度標示只在有助於理解長頁面時加入。不要自動加入換色、換語言、主題切換或其他未被要求的控制項。
- 流程圖中的 Input、Process、Output 必須能在第一眼辨識，且不依賴 hover 才能讀懂。
- 優先使用一個具體、尺寸小的教學例子，逐步展示輸入如何變成輸出；例子中的假資料必須明標「示意資料」或「教學範例」，不得偽裝成論文結果。
- 文字能被空間關係直接表達時，優先畫圖。例如細胞混合比例用細胞圖、訊號轉折用階梯線與切點、斷點證據用跨區段讀序、候選搜尋用候選格、評分用高低罰分。圖中仍須有直接標籤，不能只靠顏色或要求讀者自行推測。
- 當使用者指出文字過多、抽象或難懂時，優先把既有段落改成自足圖例，而不是在旁邊再增加一段解釋。圖例須直接顯示資料來源、數值變化、候選內容、計算結果與選擇理由；只保留不能由圖形表達的必要小字。
- 圖中的「實際觀察」必須寫出觀察的是什麼，例如「100 條讀序中 23 條支持突變（AD／DP＝23%）」，不能只標一個沒有分母與來源的百分比。
- 公式只放真正有助理解的核心關係，並同步解釋分子、分母和輸出意義。抽象符號若會造成新問題，直接在公式中換成具體名稱或鹼基例子；例如不用未定義的 A、B，而寫「T 版本讀數 ÷（C 版本讀數＋T 版本讀數）」。沒有單一公式的步驟應改用資料圖例，不硬造公式。
- 一組教學例子應盡量沿流程使用同一組數字；每一步說清楚「這一步新知道什麼」以及「排除了哪種可能」。若使用者要求新增資料來源圖、公式或解釋，不得因此刪除他已要求保留的案例圖。
- 同一組教學數字必須前後可計算且互相一致。候選卡需列出假設（例如純度、區段 DNA 份數、正常細胞基準與突變份數），評分卡需用同一組假設算出預測值；不得先畫候選 A／B，再填入無法由候選條件導出的任意百分比。
- 若用有限細胞數或「相對 DNA 單位」幫助理解，明標它是教學模型，不是軟體直接計數的細胞、讀序或實際公式；正式關係與教學模型不可混寫。
- 避免同一資訊連續用摘要句、表格與流程圖重複三次。保留最能回答問題的主視覺，其他內容只補主視覺尚未回答的資訊。
- 對「為什麼方法強」的解釋，應指出它整合了哪些互補證據、如何處理多解或雜訊，以及何種一致性條件讓結果較穩健；不要只寫「模型很準」或列工具清單。

## 術語與語言

- 繁體中文教學頁的專有名詞統一採「中文（英文或縮寫）」格式，例如「腫瘤純度（purity）」、「DNA 份數（copy number）」、「結構變異（SV）」。同一頁不要交替使用英文裸詞、縮寫裸詞與不同中文譯名。
- 工具、軟體與專案的正式名稱保留原名；在第一次出現時用一句中文說明角色，不硬翻成不存在或不通行的中文名稱。
- 檔案格式可寫成「原始定序檔（FASTQ）」、「比對檔（BAM）」、「變異檔（VCF）」。若帶 tumor／normal 前綴，先寫中文角色，再於括號保留實際名稱。
- 不使用會讓初學者誤解的代稱或比喻。若「父母兩套 DNA」只是教學近似，避免暗示資料能直接辨認父系與母系；必要時改稱「同一位置的兩種 DNA 版本」。

## 教授報告版本

頁面內容以口頭報告順序安排：研究問題 → 核心直覺 → 完整流程 → 一個算例或案例 → 為何有效 → 限制與可追問問題。每一節先給一句可以直接說出口的重點句，再提供視覺證據。

若使用者要求 PPT：

1. 使用 Presentations skill 產生真正的 `.pptx`，沿用相同敘事與視覺語言。
2. 不把長 HTML 頁面逐段截圖塞入投影片；重新排成一頁一重點的投影片。
3. 渲染並逐頁檢查溢位、字級、圖例、箭頭與對比，執行投影片測試後才交付。
4. HTML 中的下載按鈕連到已驗證的 `.pptx`；若檔案不存在或尚未驗證，不顯示可用狀態。

## 驗證清單

- 只看流程圖，能否說出 Input、主要處理與 Output？
- 不看程式碼，是否仍能理解方法？
- 每個專有名詞是否都有白話角色與例子？
- 全頁專有名詞是否一致使用「中文（英文）」格式，且工具名稱與方法步驟沒有混為一談？
- 能否從原始資料一路沿箭頭說出中間訊號與最終輸出？每個箭頭是否只有一個清楚方向，沒有文字箭頭與圖形箭頭重複？
- 抽象步驟是否已用圖或可觀察動作解釋，而不是只換一組術語？
- 局部修改後，使用者先前要求保留的範例、圖、下載功能與章節是否仍存在？
- 教學假資料是否明確標示？
- 已知觀察值、候選假設與模型輸出是否清楚分開？是否錯把 purity、ploidy 或 copy number 寫成原始資料已知？
- 同一案例的候選條件、公式、分母與預測結果是否真的算得起來？
- 論文使用的工具版本與目前實作是否分開標示？實作細節的查證層級是否如實揭露？
- 能用圖例表達的內容是否仍重複堆成長段落？
- 使用者未要求的控制項是否已移除？
- PPT 下載是否指向真實、可開啟且已檢查的 `.pptx`？
