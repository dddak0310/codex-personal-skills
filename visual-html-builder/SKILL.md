# Visual HTML Builder

把資訊重構成能快速理解與決策的單一 HTML，而不是把原文換皮貼入頁面。保持自動辨識啟用；使用者也可用 `$visual-html-builder` 明確呼叫。

## 執行流程

1. 讀取使用者提供的文字、檔案、資料與網址；辨識他想理解或決定什麼。
2. 找出核心結論、分類、指標、時間、關係、流程、優先順序、異常與風險。建立事實溯源清單（claim ledger），將每個標題結論、摘要數字、圖表序列與行動建議連到來源位置、原始欄位或計算式；無法追溯者不得呈現為事實。
3. 依資訊關係選擇最少、最合適的視覺形式。製作前讀取 [視覺與敘事規範](references/visual-design.md)。若沒有適合圖表，改用清楚的文字層級、標註與表格。
   - 若任務是論文方法導讀、研究流程教學或口頭報告輔助，另讀取 [研究方法教學模式](references/tutorial-method-mode.md)，先講概念與 Input → Process → Output，再把程式碼降為查證與補充證據。
4. 以問題與結論組織敘事，而非沿來源順序堆疊。通常依序呈現：標題與範圍、核心結論、主要視覺、支持證據、可探索細節、限制與缺口、下一步。
5. 建立單一、自包含、離線可用的 HTML，儲存至目前工作區的 `outputs/`。遵循 [實作與驗證規範](references/implementation-validation.md)。
6. 實際開啟並驗證內容、互動、響應式、配色、鍵盤操作與列印樣式；修正問題後才交付。

## 核心決策規則

- 每個視覺元件都回答一個明確問題；不為裝飾加入圖表或互動。
- 優先呈現最重要的結論、關係、差異、趨勢、流程、分布、風險、機會與下一步。
- 只在有決策價值時使用摘要卡片，最多三至四個關鍵指標。
- 大量資料先合理聚合、分組或篩選，並保留原始筆數與聚合方式。
- 不使用 3D 圖表、不透明綜合分數，或只靠顏色區分資訊。
- 不重複呈現同組資料，除非不同視覺確實帶來不同洞察。
- 修改既有 HTML 時先辨識使用者指定的局部範圍；除非使用者明確要求重做、刪除或取代，不移除既有段落、範例、互動、下載功能或已確認的視覺。新增解釋通常與既有內容並存，完成後檢查未要求變動的關鍵元件仍存在。
- 資訊不足時保留空白或標示「資料不足」；不得為完成圖表而捏造。證據不足時可不提出核心結論或下一步，不得強行補齊敘事。

## 資料忠實性

- 不改變或捏造數字、比例、趨勢、結論與因果關係。
- 不得以模型記憶、常識、版面需要或未實際讀取的網址，補齊來源未提供的日期、分類、基準值、單位、樣本數、地理位置、目標值或因果解釋；必要時標示「資料未提供」。除非使用者授權且來源已實際讀取，不加入外部事實。
- 不得擅自以補零、前值延續、平均值或其他插補方式處理缺值。若使用者要求估算，必須將輸入、方法、假設及結果明標為「估算」，並保留原始缺值狀態。
- 所有衍生數值須保留輸入欄位、公式、分母、期間、單位與四捨五入規則；百分比同時揭露分子、分母或可回查的基數。不得自行選擇有利的分母、期間或截點。
- 將「分析推論」與原始事實在文字和視覺上分開，附推論依據及合理替代解釋。不得把相關性、時間先後或共同變化寫成因果；缺乏因果識別證據時，不使用暗示因果的箭頭或措辭。
- 預測、外推與情境模擬不是事實。資料不足時不產生定量預測；可合理建模時，明標「模型估計」，揭露方法、假設、訓練資料範圍與不確定區間，不把點估計升格為核心事實。
- 來源矛盾時並列差異，不自行消除；缺值需說明處理方式。
- 顯示必要的資料來源、發布日期、資料涵蓋期間、口徑、限制與不確定性，不得混用不同日期概念。高風險內容不得用視覺效果掩蓋不確定性。
- 不把秘密、API 金鑰或敏感資訊寫入 HTML。

## 輸出與交付

- 使用簡短的小寫英文連字號檔名，例如 `research-overview.html`。
- 不覆蓋既有檔案；重名時加入日期或版本號。
- 回覆提供可點擊的 HTML 連結，並簡述來源、視覺形式、最重要結論與資料限制；若結論是推論、估算或資料不足，沿用相同標籤，不得在摘要時升格為事實。不要重貼完整 HTML。
- 若使用者要求「下載成 PPT／PowerPoint」，必須同時使用 Presentations skill 產生並驗證真正的 `.pptx`，再讓 HTML 下載按鈕連到該檔案；不得把列印、PDF 或改副檔名偽裝成 PPT。
